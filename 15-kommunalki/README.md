# Коммуналки

**Категория:** Web
**Флаг:** `SOLARCTF{W1ldc4rd_DN3_R00m}`

## Дано

Сайт в стиле старой доброй коммунальной квартиры: "бери ключ у управдома, он все обо всех знает, в домовую книгу записывает". По легенде нужно как-то попасть в чужую "комнату".

## Инфраструктура

Приложение сидит за wildcard-DNS `nip.io`: любой поддомен вида `<комната>.188.243.222.16.nip.io` резолвится в тот же сервер, а Flask-приложение выбирает нужную "комнату" по заголовку `Host`. Известные "жильцы" из легенды: `upravdom`, `baba-valya`, `sanych`, `tihonova`.

## Шаги

Регистрация полностью открытая, свою "комнату" можно завести себе самому:

```bash
curl --noproxy '*' -c jar.txt -X POST 'http://188.243.222.16.nip.io:30101/rent' \
     --data 'name=kvestolog&password=Parol123!'
```

Вход в свежесозданную комнату:

```bash
curl --noproxy '*' -c jar.txt -X POST 'http://kvestolog.188.243.222.16.nip.io:30101/enter' \
     --data 'password=Parol123!'
```

В ответ приходит кука `klyuch`, подписанная Flask (`itsdangerous`). Расшифровка полезной нагрузки даёт простой JSON `{"r": "kvestolog"}`: сервер хранит в подписанной куке только имя комнаты-владельца.

## Уязвимость

Сервер на главной странице проверяет только **подпись** куки, но не сверяет поле `r` с именем поддомена из `Host`, на котором этот запрос фактически выполняется:

```bash
curl --noproxy '*' -b jar.txt 'http://upravdom.188.243.222.16.nip.io:30101/'
```

Валидная подпись собственной куки оказывается достаточной, чтобы зайти как будто бы в комнату `upravdom`, хотя кука выписана на `kvestolog`. Поскольку куку сервер ставит на родительский домен (`Domain=188.243.222.16.nip.io`), она автоматически подходит под любой поддомен.

## Флаг

В комнате `upravdom` вместо обычной "стены" лежит "домовая книга", первая запись:

> Дом сдан. Квартирная мастерская выдала один ключ сразу на все двери — до конца ремонта.
> Ключ: `SOLARCTF{W1ldc4rd_DN3_R00m}`

Название флага прямо указывает на суть: wildcard-кука, одна дверь открывает все комнаты.

## Побочные находки

По пути встретились ещё два мелких недочёта, не нужных для флага: `POST /note/delete` принимает чужой `id` записки без проверки владельца (ещё один IDOR), а `POST /goto` делает 303-редирект на произвольный поддомен вообще без аутентификации.

## Грабли по инфраструктуре

Системный прокси (`127.0.0.1:10808`) ломает резолв nip.io-поддоменов, нужен `curl --noproxy '*'`. Автоматический `curl -L` вслед за 302 тоже не годится напрямую, потому что кука ставится уже на целевом поддомене, а не на исходном, нужно явно держать общий cookie jar через `-c`/`-b`.

## Вывод

Классическая ошибка misconfigured wildcard vhost: авторизация "жильца" построена на криптографически подписанной куке, но при рендере конкретной комнаты сервер считает валидность подписи достаточным доказательством права доступа, забыв сверить содержимое куки с реальным поддоменом запроса.
