# Все легче чем кажется

**Категория:** Forensics
**Сложность:** easy
**Флаг:** `SOLARCTF{NGC_n3v3r_sl33ps_0nl1n3}`

## Дано

Выгрузка UAC (Unix-like Artifacts Collector) с хоста `webtestinc`. Задача была чисто форензик: что-то на машине ведет себя подозрительно, нужно найти malware и достать флаг из него.

## Решение

Первым делом смотрим на список процессов из выгрузки. Среди них торчит `/usr/sbin/sshd` с PID 18400, но с одной странностью: бинарь на диске удален, то есть процесс держит открытым файл, которого уже нет в файловой системе. Классический признак подмененного илиself-deleting malware, маскирующегося под системный sshd.

UAC в таких случаях обычно вытаскивает память удаленного бинаря через `/proc/<pid>/exe`, и в выгрузке он лежит под `live_response/process/proc/18400/`. Восстанавливаем файл оттуда.

Бинарь оказался написан на Rust и слушает левый порт (TCP 41095), а не стандартный 22. Внутри куча мусора от обфускатора (похоже на связку с `aegis_vm`), что сразу намекает: строки просто так в бинаре не лежат, их собирают из частей через набор функций-декрипторов.

В коде нашлось восемь таких функций-декрипторов строк. Каждая возвращает свой кусок текста. Проблема в том, что без живого Linux-окружения под рукой (на машине только Windows, WSL/Docker не поднят) гонять ELF нативно не вариант. Решение: эмулировать сами функции через `unicorn` (ставится через pip без проблем), не трогая весь бинарь целиком, а просто подавая нужные байты на вход каждой из восьми функций и смотря, что они возвращают.

Результат интересный: ровно четыре функции (по виртуальным адресам `0x17b970`, `0x17ba90`, `0x17bc10`, `0x17bd20`) отдают кусочки настоящего флага:

```
SOLARCTF
{NGC_n3v
3r_sl33p
s_0nl1n3}
```

А вторые четыре (`0x17bef0`, `0x17c010`, `0x17c120`, `0x17c360`) отдают мусорную строку-обманку вроде `ergePAsdf^#$&!SSUAH*S`. По логике бинаря это decoy-ветка, которая используется в пути "access denied -> fallback", то есть сработала бы, если бы malware решил, что его детектят, и захотел показать фальшивый ответ.

Склеиваем четыре настоящих куска по порядку адресов и получаем флаг.

## Вывод

Основная сложность была не в криптографии, а в том, чтобы вообще понять, какие из восьми похожих функций настоящие, а какие decoy, и прогнать их без полноценной Linux-песочницы. Эмуляция через unicorn точечно по функциям оказалась быстрее, чем тащить весь ELF в полноценный sandbox.
