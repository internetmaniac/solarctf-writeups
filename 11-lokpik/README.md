# Локпик

**Категория:** Misc
**Флаг:** `SOLARCTF{5pl1t_l0ck_g0es_brr}`

## Дано

Файл `lockpick.bin`, 32220 байт. По описанию это прошивка некоего устройства-замка, которое требует 32-битный ключ разблокировки. Угадывать ключ перебором бессмысленно (2^32 вариантов), значит надо разбираться, что это за прошивка и как устроена проверка ключа изнутри.

## Определяем, что внутри

Размер и структура файла указывают на битстрим FPGA, а не на обычный firmware для микроконтроллера. Сопоставление с известными форматами показало, что это битстрим именно для Lattice iCE40 HX1K, то есть аппаратная логика "зашита" прямо в конфигурацию программируемой матрицы, а не исполняется процессором.

Для такой FPGA есть open-source тулчейн icestorm (включает `icebox`), который умеет разбирать родной формат конфигурации и превращать его в читаемые представления:

1. Сырой CRAM-дамп конвертируется в текстовый ASC-формат штатными средствами icebox.
2. Дальше `icebox_vlog.py` из проекта icestorm (его пришлось отдельно скачивать с GitHub, в системе он не стоял) превращает ASC в Verilog-нетлист: видно LUT-таблицы, carry-цепочки сумматоров и то, как они соединены между собой.

То есть по сути получаем исходную логическую схему замка, просто на уровне вентилей вместо исходного HDL-кода.

## Поиск ключа через SMT

Руками анализировать сеть из сотен LUT и carry-цепочек нереально, поэтому восстановленный нетлист не читали построчно, а скормили в Z3 как есть: описали семантику каждого LUT и переноса как булевых ограничений, 32-битный ключ объявили свободными переменными, а условие "схема разблокирована" задали как целевое ограничение. Z3 нашел единственное решение, то есть единственный ключ, удовлетворяющий всей схеме.

Интересная деталь: восстановить по битстриму, какой физический пин FPGA соответствует какому биту ключа в привычном порядке (от старшего к младшему или наоборот), штатно нельзя, таких метаданных в конфигурации просто нет. Но на результат это не влияет: Z3 ищет решение по факту логики схемы, а не по человекочитаемым номерам пинов, так что порядок бит для самого найденного ключа значения не имеет.

## Получение флага

Дальше просимулировали восстановленный нетлист с найденным Z3 ключом на входе. При правильном ключе схема на 8 выходных пинах последовательно печатает символы флага (по сути это побайтовый вывод через 8-битную шину, которая в оригинальной прошивке, видимо, вела на какой-то дисплей или UART).

Результат симуляции: `SOLARCTF{5pl1t_l0ck_g0es_brr}`.

## Вывод

Задача на реверс FPGA-логики без доступа к оригинальному HDL-коду: сырой битстрим Lattice iCE40 восстанавливается до Verilog-нетлиста через icestorm/icebox, а дальше вместо ручного разбора схемы эффективнее сразу уйти в SMT-солвер, который находит единственный 32-битный ключ по самой структуре логики, а не перебором. Финальный шаг, то есть собственно чтение флага, это просто симуляция схемы с найденным ключом.
