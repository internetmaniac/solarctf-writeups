# Последнее дело

**Категория:** Misc / стеганография
**Флаг:** `SOLARCTF{s0l4r_4ray_ds3c_r3s34rch}`

## Дано

PDF-отчёт на 65 страниц и набор файлов неизвестной программы (`solar.exe` — Windows PE64 на Haskell/GHC, `solar.s4r` — упакованный ресурс, `onnxruntime.dll`). Связка "ONNX Runtime + большой файл ресурсов + текстовый отчёт" сразу намекает на нейросетевую текстовую стеганографию: где-то в тексте отчёта слова заменены на похожие, подобранные моделью, и позиция выбранного слова среди кандидатов кодирует биты сообщения.

## Распаковка ресурса

`solar.s4r` начинается сигнатурой `S4R2` и 56-байтным заголовком с размерами и FNV-1a-64 хешами упакованных и распакованных модели и словаря. Сами данные зашифрованы потоком `xorshift64*` (отдельный seed для модели и для словаря) и дополнительно сжаты zlib:

```python
MASK64 = (1 << 64) - 1
def decrypt(packed, state):
    out = bytearray(packed)
    for offset in range(0, len(out), 8):
        state ^= state >> 12
        state ^= (state << 25) & MASK64
        state ^= state >> 27
        key = ((state * 0x2545f4914f6cdd1d) & MASK64).to_bytes(8, 'little')
        for j in range(min(8, len(out) - offset)):
            out[offset + j] ^= key[j]
    return bytes(out)
```

После распаковки и проверки длин/хешей из заголовка получаются `model.onnx` и `vocab.txt` на 83828 токенов — классическая masked language model (WordPiece-токенизация, `[MASK]`-предсказания).

## Поиск заменённых слов в PDF

Следы подмены видны не в самом тексте, а в операторах вывода `TJ` в потоках содержимого страниц: у заменённых слов интервалы кернинга между буквами отличаются по точности от соседних (не строгий признак, но хорошая эвристика для первичного отбора). Из 65 страниц так восстановлено 107 слов-кандидатов на замену, каждое с контекстным предложением.

Важные грабли при извлечении: порядок текста в content stream может не совпадать с визуальным порядком чтения страницы; нужно аккуратно сохранять пробелы на стыках перенесённых строк (вроде `Form. MaximizeBox` или `<HardBit- TOX-id>`); а если в предложении несколько одинаковых слов, маску нужно ставить именно на то конкретное вхождение, которое реально было заменено.

## Восстановление кандидатов модели

Для каждого предложения с `[MASK]` гоняется ONNX-модель (четыре входа: `input_ids`, `attention_mask`, `token_type_ids`, `mask_positions`), из полного распределения по словарю отбираются 8 кандидатов: только слова из букв, без дублей без учёта регистра, топ-8 по убыванию вероятности.

## Перестановка кандидатов через встроенную VM

Индекс слова по убыванию вероятности сам по себе ещё не бит сообщения — программа сначала переставляет восемь кандидатов через собственную маленькую VM внутри `solar.exe`. Перестановка зависит от контекста: ключ это FNV-1a-64 от строки `нормализованное_предложение<TAB>id0,...,id7` (ID кандидатов в порядке вероятности), а связь логического индекса `i` с физическим слотом внутри VM:

```python
physical = (((context >> 10) & 7) + i * (((context >> 7) & 7) | 1)) & 7
```

Множитель всегда нечётный, так что соответствие на восьми слотах взаимно однозначное и легко обращается перебором `i` от 0 до 7. Сама функция перестановки эмулировалась через Unicorn с подготовленными Haskell-объектами и заглушками рантайма (конкретные адреса входа и перехвата записи/очистки слота — в самом бинарнике).

Получив перестановку, смотрим, на каком месте в ней оказалось слово, реально стоящее в PDF — это и есть три бита (например, индекс 5 = `101`), старшим битом вперёд.

## Формат сообщения

107 носителей × 3 бита = 321 бит, из них первые 320 составляют 40-байтный кадр (последний бит — нулевое дополнение):

| Смещение | Размер | Поле |
|---|---|---|
| 0x00 | 2 байта | длина полезной нагрузки, big-endian |
| 0x02 | 34 байта | флаг |
| 0x24 | 4 байта | CRC32 полезной нагрузки, big-endian |

## Неожиданная сложность: квантованная модель чувствительна к CPU

Прогон тех же 107 предсказаний в обычном режиме и в режиме с ограничением до AVX2 (без AVX-512/VNNI) дал **разные** наборы кандидатов в части позиций, а значит и разные перестановки и разные символы на выходе. Ни один из двух цельных результатов по отдельности не проходил проверку CRC32, они расходились ровно в четырёх трёхбитных символах:

| Режим | Результат |
|---|---|
| Обычный | `SOLARCTF{s0l4r_4ray_ds3c_r3s34rch}`, CRC `cd8ca3d2` |
| AVX2 | `SOLARCTE{s0l4r[4ray_ds3c_r1s34rch}`, CRC `cd9ca3d2` |

Перебор всех 2^4 = 16 комбинаций символов из двух наблюдавшихся наборов (без ручной правки по смыслу, только реально полученные значения) даёт ровно одну, которая проходит длину, нулевое дополнение и CRC32:

```text
SOLARCTF{s0l4r_4ray_ds3c_r3s34rch}
Length: 34; CRC32: cd9ca3d2
Checked 16 numerical variants; one valid frame.
```

## Вывод

Многослойная нейросетевая стеганография: зашифрованная и сжатая MLM-модель, стеганографический выбор слов в PDF по кернингу, собственная VM на перестановку кандидатов внутри Haskell-бинарника, и финальный сюрприз в виде недетерминизма самой квантованной модели в зависимости от доступных инструкций CPU. Проверка CRC32 — единственный надёжный способ отличить правильно собранный флаг от внешне похожего, но ошибочного текста, когда часть входных данных зависит от конкретного железа.
